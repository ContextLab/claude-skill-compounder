# Issue #19 — closing the gap: plan of record

Written 2026-08-26, on `b10638f`. Issue #19 states four requirements. This is the plan to
meet all four, what is already measured, and what each deliverable is gated on.

## What issue #19 asks for, restated as four testable properties

1. **Recognition happens during the work**, not only in a post-hoc transcript read, and a
   *known* repeated mistake is caught deterministically without a model.
2. **A skill fires because the architecture forces it**, not because a reminder was read.
   The maintainer's own measurement: reminders were read past every time; only refusal
   steers.
3. **Skills compose** — one skill invokes another mid-procedure — and compose across
   scopes (project / user / public).
4. **The forge loop closes with use.** The user is told a forge started and why, told when
   the skill is ready, and told when it was *used on the problem that caused it*.

## Assumptions measured before building (the issue's own doctrine)

| # | Assumption | State |
|-|-|-|
| P0 | `PostToolUseFailure` carries the failing command and the error | **MEASURED YES** — payload holds `tool_input.command` and `error` ("Exit code 1\n<stderr>"); a failed Bash produces *only* this event, no `PostToolUse` |
| P1 | A skill created mid-session is invocable in that session (hot reload) | probing |
| P2 | Composition nests deeper than 2 | probing |
| P3 | A `PreToolUse` deny *steers* rather than merely erroring | probing (claim-gate is production precedent) |
| P4 | A project-local `.claude/skills/` skill routes automatically | probing |

## Deliverables

### D1 — `hooks/repeat-gate.sh` (requirement 1)
Deterministic, no model. Three arms on one script, dispatching on `.hook_event_name`:
- `PostToolUseFailure` → normalise the failing call to a **signature** and append it to
  `<state>/repeats/index.jsonl` with the session id and the verbatim error head.
- `PostToolUse` → the first success of the same tool in the same session after a recorded
  failure is stored as that signature's **candidate recovery**.
- `PreToolUse` → when a signature has failed in ≥ N *distinct* sessions, **deny** the call
  and name the recovery that the majority of those sessions actually used.

This is the GitHub example exactly: broken tool tried, fails, worked around; second time
the workaround is *forced*, with no session-level judgement involved.
CLI: `bin/skillrepeat` to list, explain, and forget signatures.

### D2 — `hooks/doc-gate.sh` (requirement 2)
`PreToolUse`, matcher `Bash`. On a `git push`, compute the commits about to leave
(`@{upstream}..HEAD`). If they touch code and touch no documentation, **deny**, naming the
files and instructing the session to invoke `documentation-sync`. Fails open on every
ambiguity (no upstream, not a repo, detached head, `jq`/`git` missing).

### D3 — closing the forge loop (requirement 4)
`skillforge done` keeps its ledger contract exactly (the `start`/`done` join must not
move). It additionally writes `<state>/apply-pending/<name>.json`. Two new pieces:
- `skillforge apply --name X --outcome used|declined --evidence "<verbatim>"` writes a new
  ledger event `apply` — invisible to the existing join, per the "add an event freely,
  never widen a selector to a negation" rule — and clears the marker.
- `hooks/apply-gate.sh` on `Stop` **refuses to end the turn** while a forge closed in this
  session has never been applied. Requirement 4 enforced by refusal, per requirement 2.
Status line grows a pending-apply segment: `⚑ <name> forged — not yet used`.

### D4 — composed skills (requirement 3)
Forged through the real A→E pipeline, cold red-teamers, never forks:
- **`documentation-sync`** — leaf. Compares code to docs, updates. Called by D2's deny.
- **`finish-task`** — the deterministic end-of-task sequence from issue #19's first
  bullet: red-team → full test + lint sweep → notes → **invoke `documentation-sync`** →
  commit → PR. Composition, in production, on this repository's own work.

### D5 — verification (the /goal bar)
Not "tests pass". Each of these, run for real and recorded:
- The doc gate denies a real `git push` in this repository, and the deny is quoted.
- The repeat gate denies a real repeated failure across two real headless sessions.
- `finish-task` is invoked on this branch and observably invokes `documentation-sync`.
- Routing probes at the 3-run floor for every new skill, `partial` reported as `partial`.
- `skillreport` before and after, with harness traffic excluded as it already is.

### D6 — documentation
`README.md`, `docs/DESIGN.md` (local rationale), `docs/CLAUDE-CODE-BEHAVIOR.md` (the five
platform measurements above), `.claude/CLAUDE.md`, `notes/`, and a comment on issue #19.

## Order, and what each step is gated on

D1 and D2 are gated on P0 only (measured). D3 is gated on nothing. D4 is gated on P1 and
P2. D5 is gated on all of the above. Nothing is built past a probe that comes back NO.
