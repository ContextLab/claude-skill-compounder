# 2026-08-24 — origin of claude-skill-compounder

Extracted from a working session in `~` where the idea was first built directly into
`~/.claude/` (CLAUDE.md doctrine + hooks + status line), then distilled into this repo.

## What exists

- `skills/skill-compounder/SKILL.md` — the doctrine, as an installable skill
- `hooks/compound-improvement.sh` — the two throttled reminders
- `bin/skillforge` + `statusline/` — the live progress animation
- `skill_compounder/installer.py` — non-destructive settings.json merge
- 45 tests, no mocks (`./run_tests.sh`)

## Verified platform behavior (see docs/DESIGN.md)

- Skills hot-reload mid-session, with a ~1 tool round-trip lag
- `$CLAUDE_CODE_SESSION_ID` != the `.session_id` hooks and the status line receive
- The status line is the only continuously-animatable surface

## Open questions for the next session

- The forging protocol is written but has not yet been *run* end to end on a real
  candidate skill. Doing that once is the highest-value next step — it is the only way to
  learn where the protocol itself is under-specified.
- No packaging as a Claude Code plugin/marketplace entry yet; install is script-based.
- The threshold constants (>15 min, >=2 occurrences, 12 edits, 20 min) are first guesses.
  They should be revisited after real usage.
- Retirement flow (`~/.claude/skills-archive/`) is specified but untested in practice.
- Consider a `skillforge` subcommand that records forge history, so the repo can report
  what has been forged and whether those skills are actually getting used.
